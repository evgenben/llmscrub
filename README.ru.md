# llmscrub

**Локальное обратимое обезличивание конфигов и логов Linux перед отправкой в ИИ.**

[English version](README.md)

Вы проводите аудит или разбираете проблему на серверах и хотите помощи ChatGPT, Claude или другого ИИ, но не имеете права раскрывать внутренние IP-адреса, домены, имена хостов, пользователей и секреты (PCI DSS, NDA, здравый смысл). llmscrub заменяет их согласованными псевдонимами, сохраняет структуру, чтобы ИИ мог её анализировать, а затем **переводит ответ ИИ обратно** на ваши реальные значения.

Всё работает локально: нет сетевых соединений, нет зависимостей кроме стандартной библиотеки Python и Tk. Словарь соответствий живёт только в памяти окна.

![Обезличивание журнала и auth.log](docs/screenshot-mask.png)

## Как это работает

1. Вставьте конфиг, лог или вывод команды в **левую** панель и нажмите **Обезличить →** (Ctrl+Enter).
2. В **правой** панели тот же текст, в котором заменены все чувствительные значения: `db01.acme.lan` → `host01.org01.example`, `ivanov` → `user01`, `10.20.17.88` → `10.211.144.88`, пароли → `<SECRET_01>`. Одно и то же значение всегда получает один и тот же псевдоним, поэтому ИИ видит связную картину.
3. **Копировать для ИИ** сначала проверяет текст: если в нём остались исходные значения или необезличенные IP, они подсвечиваются, и копирование требует подтверждения.
4. Вставьте ответ ИИ в **правую** панель и нажмите **← Восстановить** (Ctrl+Shift+Enter). В левой панели появится ответ с вашими реальными значениями.

![Восстановление ответа ИИ](docs/screenshot-restore.png)

Перед выполнением команд просмотрите подсветку слева:

| Цвет | Значение |
|---|---|
| зелёный | заменено / восстановлено по словарю сессии |
| голубой | адрес **вычислен** по известному префиксу — например, ИИ предложил шлюз `.1` в подставной подсети; подсети сохраняются, поэтому адрес восстанавливается правильно |
| жёлтый | значения нет в сессии (ИИ его придумал или взял из примера) — оставлено как есть |
| оранжевый | неоднозначно — варианты перечислены в предупреждениях |
| красный | плейсхолдер секрета вида `<SECRET_01>` — секреты не восстанавливаются, подставьте значение сами |

Ничего не выполняется автоматически.

## Установка

Требования: Linux, Python 3.11 или новее с Tk.

```bash
sudo apt install python3-tk pipx git      # Debian / Ubuntu
pipx ensurepath                           # один раз; затем откройте новый терминал
pipx install git+https://github.com/evgenben/llmscrub
llmscrub init-config                      # создаст ~/.config/llmscrub/config.toml (права 0600)
nano ~/.config/llmscrub/config.toml       # впишите свои DNS-суффиксы и название компании
llmscrub                                  # откроет окно
```

В других дистрибутивах установите Tk для Python (`python3-tkinter` в Fedora, `tk` в Arch). Обновление: `pipx upgrade llmscrub`. Без pipx: склонируйте репозиторий и запускайте `./bin/llmscrub`.

**Заполните конфиг.** Без внутренних DNS-суффиксов и названия компании домены и Kerberos-realm почти не распознаются. Сам конфиг в ИИ не передавайте. При русской локали `init-config` создаёт конфиг с комментариями на русском.

## Язык

Интерфейс на английском и русском. Язык выбирается по локали системы (`LANG`, `LC_MESSAGES`, `LC_ALL`, `LANGUAGE`); переопределить можно переменной `LLMSCRUB_LANG=en|ru` или флагом `--lang en|ru`.

## Что и как подменяется

| Что | Где находится | Замена | Обратимо |
|---|---|---|---|
| IPv4, CIDR, маски | везде; `a.b.c.d/NN`, `addr mask` | с сохранением класса, префиксов и последнего октета | да |
| PTR-зоны | `30.20.10.in-addr.arpa` | согласованно с IP | да |
| FQDN под вашими суффиксами | везде | `host01.zone01.org01.example` | да |
| Kerberos-realm, LDAP DN | `ACME.LAN`, `dc=acme,dc=lan` | `ORG01.EXAMPLE`, `dc=org01,dc=example` | да |
| Короткие имена хостов | префикс syslog, prompt, `/etc/hosts`, fstab, rsyslog, URI, ssh_config, конфиг | `host01` | да |
| Пользователи | auth.log, sudo, su, PAM, audit, passwd/shadow/group, sudoers, AllowUsers, sssd, `/home/x`, e-mail, принципалы, `ls -l`, `id`, `last` | `user01` | да |
| Имена людей | LDIF `cn/sn/givenName/displayName`, GECOS | `name01` | да |
| Строки из конфига | подстрока без учёта регистра, в т.ч. в путях и subject сертификатов | `org01` | да |
| Пароли и токены | `key = value` по ключевым словам, `user:pass@` в URI, `Authorization`, `.netrc`, `sasl_passwd`, `curl -u`, `mysql -p`, `sshpass`, SNMP community, PSK, JWT, ключи облаков | `<SECRET_n>` | **нет** |
| Хеши паролей | `$y$`, `$6$`, `$2b$`, `{SSHA}` … | `<HASH_n>` | **нет** |
| Ключи и сертификаты | PEM-блоки, inline-блоки OpenVPN | `<KEY_n>`, `<CERT_n>` | **нет** |
| Номера карт | 13–19 цифр с проверкой по Луну | `<PAN_n>` | **нет** |
| Hex-поля audit.log | `proctitle=`, `cmd=`, `acct=` … | декодируются, обезличиваются, кодируются обратно | — |

Одинаковые секреты получают одинаковый плейсхолдер: ИИ видит повторное использование пароля, но не сам пароль.

**Не трогается:** loopback, `0.0.0.0`, маски, multicast, link-local, документационные сети, адреса из `ips.keep`, системные учётки (`root`, `www-data`, `sshd` …), общие метки DNS (`www`, `mail`, `ldap`, `prod` …), MAC-адреса, булевы значения и PAM-строки (`password requisite pam_deny.so`), пути к файлам ключей.

## Командная строка

```bash
journalctl -u nginx --since today | llmscrub mask > for_ai.txt
llmscrub unmask < ai_answer.txt
llmscrub check < something.txt         # код выхода 1, если найдены исходные значения
llmscrub session show | clear
```

CLI хранит словарь в `$XDG_RUNTIME_DIR/llmscrub/session.json` — это tmpfs, файл исчезает при выходе из системы, права 0600. Если в результате `mask` найдена утечка, вывод блокируется (код 2); `--force` выводит его всё равно.

## Ограничения

- Распознавание основано на правилах. **Всегда просматривайте правую панель перед отправкой.**
- Без конфига домены и realm почти не распознаются.
- Секрет без ключевого слова (пароль в свободном тексте, аргумент нестандартной утилиты) не найдётся. Проверка утечки поймает его, только если тот же секрет уже был найден в этой сессии.
- Base64 и другие кодировки не декодируются, кроме hex-полей audit.log. Basic-авторизация ловится по заголовку `Authorization`.
- Версии из четырёх чисел (`6.8.0.45`) похожи на IP и подменяются.
- IPv6 не обрабатывается.
- Для публичных сетей короче /24 вложенность подсетей может не сохраниться; для частных сетей она сохраняется всегда.
- Адрес вида `a.b.c.0` без маски в редких случаях восстанавливается неоднозначно; такие места помечаются.
- Структура остаётся видимой сознательно: количество хостов, порты, версии ПО, пути. Иначе ИИ не сможет ничего проанализировать.
- **История буфера обмена.** Менеджеры буфера обмена (например, Clipboard History для GNOME) сохраняют всё, что вы копируете, в том числе исходные конфиги. Отключите их на время работы. При закрытии окна буфер очищается.
- Закрыли окно — словарь потерян, ответы на старые тексты не восстановить.

## Соответствие требованиям

llmscrub — техническая мера. Сам по себе он не разрешает передачу данных внешнему ИИ. Опишите процесс в документации аудита (какие данные, как обезличиваются, кто проверяет результат) и согласуйте его с ответственным за политику (и с QSA, если речь о PCI DSS).

## Сообщения о проблемах

Только **вымышленные данные** — никогда не публикуйте реальные конфиги и логи, даже частично скрытые. Подробнее в [SECURITY.md](SECURITY.md).

## Разработка

```bash
python3 -m unittest -v tests.test_engine
```

Тесты используют только вымышленные данные из `tests/samples/`. Они проверяют, что в результате нет исходных значений, что после восстановления получается исходный текст (кроме секретов), а также свойства отображения IP. Настоящие публичные адреса генерируются во время теста, поэтому в репозитории их нет.
